- Windows build-lock gotcha: a running dev/prod server locks `.next` files, so rebuilds die with EPERM unlinking (e.g. `.next/node_modules/@solarisdk/browser-…`) while the user only sees "build worker exited with code: 1" and `npm start` failing on a missing `prerender-manifest.json`. Fix: stop the server, wipe `.next` (`cmd.exe /c "rmdir /s /q .next"`), rebuild. When the user pastes a cryptic build-worker exit, reproduce the real build to surface the hidden error instead of guessing. Confidence: 0.75

Prefer quick foreground runs with hard internal caps (Promise.race + process.exit, e.g. 25s dial timeout, 90–110s total) over long background waits; kill hung tasks immediately on user report; confirm live external state (e.g. the session actually exists via a quick API call) before telling the user a test is running. Fix lives in the harness: a corrected browser MCP server (`/tmp/solari-browser-mcp.mjs`, written into the sandbox by `app/api/run/route.ts` on every run) that applies `session.storageState` cookies + localStorage client-side via patchright and returns `cookiesApplied` in the create response. Confidence: 0.9
